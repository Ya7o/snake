PATCH 1036 - asset path check

Target GitHub Pages URL:
- https://ya7o.github.io/snake/

Vite config:
- vite.config.ts exists.
- Current config has server and preview only.
- No base value is configured.
- Vite therefore uses its default base: /

Built index.html path findings:
- link rel="icon" href="/favicon.svg"
- link rel="manifest" href="/site.webmanifest"
- script type="module" crossorigin src="/assets/index-Bdf8i75G.js"

Risk:
- Under https://ya7o.github.io/snake/, root-absolute URLs resolve against https://ya7o.github.io/ instead of https://ya7o.github.io/snake/.
- The built JS would be requested as https://ya7o.github.io/assets/index-Bdf8i75G.js.
- The actual project asset would be under https://ya7o.github.io/snake/assets/index-Bdf8i75G.js.
- Result: likely blank page because the entry JS 404s before Phaser starts.

Runtime asset references in source/build:
- Most game assets use relative paths such as assets/ui/..., assets/universes/..., assets/openmoji/..., assets/audio/...
- These relative paths are generally compatible with /snake/ when loaded from https://ya7o.github.io/snake/.
- Runtime universe assets in src/assets/runtimeUniverseAssets.ts use root-absolute paths: /assets/runtime/universes/...
- Those runtime assets will 404 under /snake/ unless paths are made base-aware or changed to relative.

Specific root-absolute runtime asset examples:
- /assets/runtime/universes/sonic/pickup_ring.png
- /assets/runtime/universes/streets/obstacle_crowd.png
- /assets/runtime/universes/fighter/boss_final_challenger.png
- /assets/runtime/universes/outrun/boss_turbo_rival.png
- /assets/runtime/universes/shinobi/boss_shadow_ninja.png
- /assets/runtime/universes/kombat/boss_dragon_gate.png
- /assets/runtime/universes/paperboy/boss_neighborhood_chaos.png

Public asset copy:
- public/assets are copied into dist/assets.
- dist contains runtime/universes assets for seven non-castle universes.
- dist contains openmoji, audio, frames, level-intros, map, ui and universes assets.

Audio findings:
- Existing copied audio files:
  - assets/audio/pickup_magic.wav
  - assets/audio/collision_hit.wav
  - assets/audio/stage_clear.wav
  - assets/audio/ui_button.wav
  - assets/audio/danger_alert.wav
- Referenced but missing from public/assets/audio:
  - assets/audio/game_over.wav
  - assets/audio/boss_hit.wav
  - assets/audio/boss_clear.wav
- Missing audio does not block initial render because AudioSystem uses fallback tones if playback fails, but network 404s may appear when those events fire.

Manifest/PWA path findings:
- public/site.webmanifest has start_url "." which is project-path friendly.
- Its icon src is "/favicon.svg", which is root-absolute and will point outside /snake/ on GitHub Pages.
- index.html also uses root-absolute /favicon.svg and /site.webmanifest.

Recommendation:
- PATCH 1037 should configure a GitHub Pages compatible base.
- For this repository URL, the most direct Vite setting is base: "/snake/".
- Also update source/runtime asset references that are currently root-absolute, especially runtimeUniverseAssets.ts.
- Alternative base: "./" can make the built entry relative and portable, but it should be tested with Phaser asset loading and any future nested routes before choosing it.

Conclusion:
- Build works locally.
- Static deploy under the GitHub Pages project path is not ready as-is.
- Main failure mode is blank page from root-absolute built entry script.
